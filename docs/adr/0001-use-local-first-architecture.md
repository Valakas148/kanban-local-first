# 1. Використання Local-First архітектури з можливістю майбутньої синхронізації

- **Дата:** 2026-11-02
- **Статус:** Прийнято (Accepted)

## Контекст

Розробляємо Kanban-застосунок, який повинен працювати миттєво (без затримок мережі) та підтримувати повноцінну роботу в автономному режимі (offline-first). У майбутньому планується додавання бекенду для синхронізації даних між пристроями.

## Рішення

Обрано **Local-First** підхід:

1. Клієнтський стан і UI працюють виключно з локальною базою даних (IndexedDB / PGLite).
2. Доменна логіка (`features/*/model`) є абсолютно чистою й ізольованою від UI (React) та механізмів збереження.
3. Доступ до даних реалізується через патерн **Repository** (`IDataRepository`), що дозволить підключити Sync Engine без переписання UI.

## Наслідки

- **Плюси:**
  - 0ms latency для дій користувача.
  - Повна робота offline.
  - Чітке розділення шарів за Clean Architecture / FSD.
- **Мінуси / Складнощі:**
  - Необхідність обробки конфліктів версій (Conflict Resolution) при додаванні синхронізації з сервером.
  - Необхідність міграцій локальної бази даних прямо в браузері.
